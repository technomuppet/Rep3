## New Renderer Actually Being Used?

### Evidence via Source Code

- `ExerciseLibraryScreen.kt` line 299: `ExerciseAnimationView(ex)` — calls ExerciseAnimationView.
- `ExerciseAnimationView.kt`:
  - `when (mode = remember(... VisualEngineAdapter.resolveAnimation))` — resolves via adapter.
  - `is SkeletalEngine -> CommercialAnimationCanvas`
  - Inside CommercialAnimationCanvas: `SkeletalRenderer.drawCommercial` with spec.
  - `SkeletalRenderer.drawCommercial` -> `BodyOrientationEngine.orient` -> `LayeredRenderingPipeline.drawPipeline` -> `HumanBodyRenderer.drawHumanBody` volumetric.
  - Also uses `BarPathEngine.calculateBarPosition`, `HybridSolver.solve`, `CentreOfMassCalculator.calculate`, `StabilisationEngine.evaluate`, `drawCoachingOverlay` COM and bar path dots.

- **Conclusion:** Yes, new commercial volumetric body renderer + modular equipment + hybrid IK + COM + bar path is actually driving UI in main path.

### Legacy Renderers No Longer Driving UI?

- `LegacyExerciseAnimationView` exists inside same file, only invoked if `VisualEngineAdapter` returns `LegacyStickFigure` on exception.
- `VisualEngineAdapter.resolveAnimation` returns `SkeletalEngine` with commercial timeline in normal case (exercise-specific first, family fallback). Only on exception does it return LegacyStickFigure.
- So legacy not driving primary UI, only fallback on error.

- `MuscleBodyDiagram.kt`: `when (VisualEngineAdapter.resolveAnatomy)` -> `VectorEngine` (new) vs `LegacyBoxes` (old). Prefers vector engine if primary/secondary muscles non-empty, which is true for most exercises (primaryMuscles from JSON). So new vector anatomy is primary, legacy boxes fallback only if empty.

- Old `EquipmentAnchoring.kt` (averaging wrists single line) — grep shows no usage in new SkeletalRenderer or layered pipeline. Only file itself defines it, not imported elsewhere except possibly old tests. So not driving UI.

- Old `ExerciseAnimation.kt` (Cartesian Points lerp rubber-banding) — only used in legacy fallback path `ExerciseAnimation.clip(exercise)`. Not driving main.

**Conclusion:** Legacy renderers no longer drive main UI, only fallback safety. New engine is active.

## Dark Mode / Light Mode / Scaling / Rotation

- **Code Analysis:**
  - `HumanBodyRenderer.BodyPalette.fromMaterial(primary, onSurface)` derives skin neutral warm #D8BFA0, shirt = primary color (from MaterialTheme), shorts #2E2E3A, shoe #1A1A1A, outline onSurface alpha 0.35. So dark/light theme adapts via primary/onSurface from MaterialTheme, skin stays neutral (acceptable).
  - Scaling: referenceSize = min(width,height)*0.32 ensures body scales cleanly across display sizes. Thickness factors multiplied by referenceSize. Torso width from shoulderWidthScreen via hypot, so scales with canvas width.
  - Rotation: BodyOrientationEngine rotates upper vs lower around pelvis via cos/sin, handles standing, seated, supine -90, prone 90, incline +30, decline -15, hanging -0.15 shift. So rotation supported.
  - Screen sizes: Canvas fillMaxWidth height 240dp, toScreen uses width*x height*y, so responsive.
  - Landscape/portrait: referenceSize uses min(width,height) so body not stretched, but aspect ratio of canvas height 240dp fixed width fillMaxWidth may be wider in landscape, still scales.
  - Tablet/phone: same scaling.

- **No runtime test possible**, but code suggests handles.

## Animation Quality, Playback, Looping, Interpolation, Frame Pacing

- **Playback:** LaunchedEffect withFrameNanos loop deltaSeconds clamped 0..0.05, playing boolean pause, restart sets elapsed 0 and playing true. Good.
- **Looping:** SkeletalTimeline mode PING_PONG (default) for most, LOOP for some, ONCE for others. PING_PONG reverses via cycleTime = duration*2 - cycle if cycle > duration, creating back-and-forth without jump. Good.
- **Interpolation:** PoseInterpolator now shortest-angle diff handling wrap -180..180, preservation all joints, clamping via BiomechanicalJointModel realistic limits, EASE_IN_OUT_CUBIC added smoother.
- **Frame pacing:** Delta clamped to 0.05 sec max avoids huge jumps on jank, elapsedSeconds accumulates.
- **Canvas performance:** drawCommercial called per frame, does orientation, layered pipeline, body 60 draw ops, equipment 7 ops, coaching overlay 5 dots. Theoretical 60fps high-end.
- **Recomposition:** Issue — elapsedSeconds mutableFloatStateOf triggers Column recomposition each frame, Row controls also recompose. Should isolate Canvas composable. Not fixed in RC20.3, noted as tech debt.
